# Prompt Recipes

Use these as scaffolds, not fixed art direction. Preserve the current product and brand.

## Store screenshot composite

```text
Use case: ads-marketing
Asset type: <store/platform/device/locale> listing screenshot
Input images: Image 1 is the real app screen and must remain accurate; Image 2 is the mascot identity reference; Image 3 is the brand palette reference.
Primary request: Present the real screen as a premium store-listing frame that communicates <single benefit>.
Composition/framing: <headline safe area>; product screen occupies <percentage>; mascot supports but does not obscure primary UI.
Style/medium: polished mobile product campaign, consistent with the existing screenshot set.
Text (verbatim): "<headline>" and "<optional support line>".
Constraints: preserve all visible UI text, controls, values, layout, and screen identity; do not invent functionality; no watermark.
Avoid: generic gradient poster, excessive props, tiny app screen, repeated headline, fake ratings, fake testimonials.
```

## Portrait editorial system — hero frame

Use this after reading `portrait-editorial-system.md` and inspecting the bundled reference set.

```text
Use case: ads-marketing
Asset type: finished <platform/device/locale> portrait store screenshot
Input images: Image 1 is the authentic app screen and the only product-content source; Image 2 is the canonical brand/mascot identity reference; Images 3+ are optional palette assets. Do not borrow UI from brand references.
Primary request: Build the first frame of a cohesive premium store campaign around the single benefit <benefit>. The result must read as an editorial product poster, not a phone screenshot pasted on a gradient.
Text (verbatim): headline "<headline>"; support line "<support line>".
Composition/framing: reserve roughly the top 22–25% for a huge, high-contrast headline of at most two lines and one compact support line. Begin the authentic product panel around 25–30% from the top. Make the product panel roughly 90–96% of canvas width and let it continue to or beyond the bottom edge. Place the mascot/brand graphic across the transition between headline and product panel without covering critical UI.
Style/medium: polished mobile product editorial, warm tactile background, feature-specific accent color, restrained rounded abstract shapes and small line-art cues, soft depth, consistent brand illustration.
Hierarchy: headline first, authentic product second, mascot/brand third, decoration last.
Constraints: preserve the app screen's real navigation, labels, content, values, and function; no invented capabilities, ratings, testimonials, prices, or Apple/Google marks; exact localized headline; no watermark.
Avoid: tiny device mockup, centered phone floating in empty space, generic gradient-only background, multiple competing headlines, text below thumbnail readability, full-screen lifestyle photo, clip-art scatter, unrelated mascot pose, fake UI.
```

## Portrait editorial system — subsequent frame

```text
Use case: ads-marketing
Asset type: next frame in an already approved portrait store screenshot campaign
Input images: Image 1 is the new authentic app screen and the only content/UI source; Image 2 is the canonical mascot/brand identity source; Image 3 is the previously approved store frame and is the only composition, typography-scale, depth, texture, and campaign-style reference.
Primary request: Create the next campaign frame for <benefit>. Transfer the visual system of Image 3, not its product content. Replace the product presentation with Image 1 and use Image 2 only for identity-consistent brand integration.
Text (verbatim): headline "<headline>"; support line "<support line>".
Composition/framing: match Image 3's headline scale, top-zone ratio, product-panel width/start, corner language, shadow softness, visual density, and mascot overlap. Allow feature-specific accent color <accent> while preserving the shared warm base.
Constraints: preserve Image 1's real UI; do not copy UI, words, numbers, or feature claims from Image 3; do not redesign the mascot; no new claims; no watermark.
Avoid: a different campaign, smaller UI, weaker headline, generic gradient, independent poster style, duplicated content from Image 3.
```

## Targeted campaign correction

```text
Change only <one failed quality gate>. Keep the authentic product UI, exact headline and support line, approved frame grid, brand identity, product-panel scale, background texture, and all other approved details unchanged. Compare against the approved reference frame before finalizing. Add no new claims or objects.
```

## Splash / launch artwork

```text
Use case: precise-object-edit
Asset type: native launch screen master artwork
Input images: Image 1 is the current launch artwork; Image 2 is the canonical mascot/logo.
Primary request: Create a calm, brand-recognizable transition into the first app screen using subtle atmospheric layers.
Composition/framing: keep all important content in the central crop-safe area; generous negative space; no edge-critical details.
Style/medium: polished brand illustration with restrained texture.
Constraints: preserve mascot/logo identity; no marketing headline, slogan, CTA, fake UI, device frame, or watermark.
Avoid: store-ad layout, dense decoration, slow cinematic scene, text-heavy composition.
```

## App icon exploration

```text
Use case: logo-brand
Asset type: app icon master
Input images: mascot/logo identity references.
Primary request: Create a single bold recognizable mark that survives at 29 px and 1024 px.
Composition/framing: centered face or symbol, strong silhouette, generous internal padding.
Constraints: square master, no transparency for final store upload, no tiny text, no screenshot UI, no external border baked in.
Avoid: full-body scene, many props, thin line work, photorealism, illegible initials.
```

## Targeted revision

