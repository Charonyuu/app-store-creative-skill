# Store Screenshot Playbook

## 1. Discovery

Collect before designing:

- app name, category, audience, locale, paid/free positioning;
- real feature inventory and working routes;
- mascot, logo, brand palette, type style, and existing launch/icon assets;
- official current platform requirements;
- clean device captures at consistent time, language, account state, and status bar.

If competitor research is useful, study patterns rather than cloning a specific listing. Record what the first frame promises, how much text appears, phone scale, color rhythm, and how the sequence progresses.

## 2. Narrative architecture

Use the first three frames for the strongest acquisition story:

1. **Core transformation:** what improves for the user?
2. **Differentiating loop:** why is this easier or more effective here?
3. **Proof of breadth or feedback:** what meaningful capability completes the story?

Later frames can show depth, personalization, review/history, pricing value, or a secondary mode. Avoid a feature-menu sequence where every headline is merely a tab name.

For each frame, define:

- user promise;
- real source screen;
- one dominant focal point;
- short headline;
- optional one-line support copy;
- visual accent and mascot role.

## 3. Copy rules

- Prefer 4–10 headline words in English or one compact Traditional Chinese line.
- Use specific outcomes: `每天 5 分鐘，開口更自然` is stronger than `口說功能`.
- Avoid unverified superlatives, medical/educational guarantees, fake rankings, and fake testimonials.
- Keep terminology consistent with the product UI.
- Generate localized copy intentionally; do not squeeze translations into the original layout.

## 4. Composition system

Lock a reusable grid across the set:

- top safe margin and headline baseline;
- phone/screen width and lower crop;
- mascot placement zones;
- text alignment;
- background family and feature accent colors;
- corner radius, shadow softness, and illustration scale.

Vary the scene enough to keep the carousel interesting, but retain one brand system. Screens should remain legible at small App Store thumbnail size. Crop unimportant UI before shrinking the whole screen too far.

## 5. Real-screen capture

- Seed realistic but non-sensitive data.
- Use the same locale, clock, battery style, and device family.
- Capture modal states only when they prove the advertised benefit.
- Remove debug banners, localhost labels, browser chrome, simulator controls, pointer cursors, and test fixtures that look fake.
- Keep source captures unchanged in a dedicated folder. Composite from copies.

## 6. Image generation

Use image generation for presentation, atmosphere, mascot actions, or a coherent campaign scene—not to invent the core product screen. Give input images explicit roles:

- edit target;
- exact UI insert to preserve;
- mascot identity reference;
- palette/style reference.

Generate distinct frames in separate calls. Review one frame before extending the system. If text fidelity fails, make a targeted correction or use a deterministic layout method for text while keeping raster scenery generated.

## 7. Localization

- Design for expansion instead of scaling all text down.
- Keep punctuation and script conventions native to the locale.
- Inspect every glyph at 100%.
- Store variants in locale-specific folders and document the mapping in the manifest.

## 8. QA checklist

### Visual

- Headline is readable at thumbnail size.
- UI is authentic and not materially altered.
- No clipped text, incorrect glyphs, broken hands/mascots, duplicate UI, or accidental watermarks.
- All frames share type, margins, device scale, and color logic.
- First three frames tell a coherent story.

### Submission

- Dimensions match current official documentation.
- Orientation and device family match the listing slot.
- Files use supported formats and color mode.
- Alpha/transparency complies with the store.
- Screenshot count is within current limits.
- Claims, prices, subscriptions, and third-party marks are accurate.

### Packaging

- Finals are numerically ordered.
- Source captures, drafts, and finals are separated.
- Manifest records locale, dimensions, source mapping, and generation prompts.
